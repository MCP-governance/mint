# 문제 해결

[안내서 홈](README.md) · [처음 시작하기](getting-started.md) · [호출 기록 읽기](call-records.md)

먼저 문제가 **로그인**, **PC 연결**, **모델 로그인**, **MCP 사용 권한**, **개별 호출** 중 어디서 생겼는지 구분합니다. 같은 쓰기·실행 요청을 반복하기 전에 실제 실행 결과를 확인합니다.

## 로그인과 PC 연결

| 증상 | 먼저 확인 | 다음 조치 |
| --- | --- | --- |
| MINT 페이지가 열리지 않음 | 조직이 안내한 주소·사내망 또는 VPN 연결 | 관리자에게 접속 주소와 서버 상태 확인을 요청합니다. |
| 브라우저 인증서 경고 | 접속 이름·인증서 이름·별도로 받은 CA 지문 | 관리자가 인증서 체인과 신뢰 설정을 확인합니다. |
| 아이디·비밀번호 오류 | MINT 계정인지, 가입 승인이 끝났는지 | 계정 상태를 관리자에게 확인합니다. 모델 계정과 구분합니다. |
| 계정 중지·잠김·삭제 메시지 | 표시된 계정 상태 | 관리자가 **사용자 관리**에서 사용·잠김 상태 또는 복구 여부를 확인합니다. |
| SSO 계정이 연결되지 않음 | 조직의 SSO 사용자와 MINT 계정 매핑 | 관리자가 SSO 설정과 계정 연결을 확인합니다. |
| 로그인 시도가 너무 많음 | 로그인 화면의 안내 | 잠시 후 다시 시도합니다. 계정 잠김 여부도 확인합니다. |
| 로그인 만료 | 유휴·최대 유지 시간 또는 인증 만료 메시지 | 다시 로그인하고 진행 중이던 작업의 처리 결과를 확인합니다. |
| 설치 완료 뒤 활성화 대기 | 설치 모드와 PC 이름, 엔드포인트 식별자 | 관리자가 **엔드포인트 관리 → 엔드포인트**에서 점검과 활성화를 확인합니다. |
| 설치 파일 만료·실행 실패 | 운영체제, 다운로드 시각과 오류 | 새 파일을 받아 설치합니다. macOS 파일은 5분 이내·1회용입니다. |

Windows·Linux는 새 터미널에서 `mint --check`로 연결을 점검합니다. Linux 격리 계정은 `sudo mint --check`를 사용합니다. Windows에서는 트레이의 **다시 연결**도 사용할 수 있습니다.

모델 응답만 실패하면 `mint login claude` 또는 `mint login codex`로 해당 모델 로그인을 확인합니다. MINT에 로그인되어 있거나 PC가 활성이라고 해서 모델 계정의 이용 가능 상태까지 보장하지는 않습니다.

운영체제별 설치·제거·재설치와 macOS 상태 파일은 [직원 PC 키트](../../endpoint-agent/README.md)에 있습니다.

## MCP가 안 보이거나 호출할 수 없음

| 증상 | 확인할 내용 |
| --- | --- |
| 사용 가능한 MCP가 없음 | 도입 승인과 등록이 완료되었는지, 사용 대상에 포함되는지, 기한이 남았는지 확인합니다. |
| PC의 도구 목록이 갱신되지 않음 | 엔드포인트 활성화·최근 보고·관리형 설정 적용 상태를 확인합니다. |
| 검증 완료인데 사용 불가 | 검증 완료와 도입 승인·등록은 별개입니다. 관리자에게 최종 승인과 등록 결과를 확인합니다. |
| 엔드포인트 실행으로 재승인 필요 | 관리자가 실행 방식·범위·환경 정보를 다시 검토해야 합니다. |
| 도구 이용 동의 요청 | 웹 콘솔 **도구 이용 동의**에서 목적·입력·외부 목적지를 확인합니다. |
| 본인 신청을 승인할 수 없음 | 기본은 독립 승인입니다. 다른 관리자에게 검토를 요청합니다. |
| 1차 승인 후에도 등록되지 않음 | 높은 위험 등급의 추가 승인 단계와 차단 사유를 확인합니다. |
| 승인했는데 호출이 차단됨 | 호출 상세의 정책 사유를 확인합니다. 승인 범위·사용 기한·계약·동의·서버 상태는 별도로 판정합니다. |
| 원격 MCP에서 인증 오류 | 필요한 서비스 자격을 관리자에게 확인합니다. 직원용 서비스 계정 연결 화면은 제공하지 않습니다. |
| 승인 소스는 받았지만 실행 실패 | 소스 다운로드 권한과 실행 승인은 별개입니다. 플랫폼·런타임·의존성·이미지·승인 매니페스트를 확인합니다. |

## 호출 결과를 받지 못함

**호출 기록 → 목록 → 해당 호출 → 실행 결과**를 엽니다.

1. **전송 안 함 / 실행 안 함**이면 판정 사유와 필요한 승인·설정을 확인합니다.
2. **실행됨 + 응답 보류**면 외부 시스템에 반영된 결과를 확인합니다. 응답을 못 받았어도 처리는 끝났을 수 있습니다.
3. **실행 미확인**이면 관리자가 실제 처리 결과를 대조한 뒤 **대시보드 → 실행 결과 확인**에서 기록합니다.
4. **승인 대기**면 관리자 검토와 만료 상태를 확인합니다. 승인이 실제 실행으로 이어질 수 있으므로 중복 요청을 피합니다.

기록이 없으면 조회 기간, MCP 서버와 호출 유형 필터를 확인합니다. 연결 거부는 **MCP 연결** 유형으로 찾습니다. 게이트웨이를 거치지 않은 활동은 게이트웨이 기록에 없을 수 있습니다.

## 관리자가 확인할 운영 문제

| 증상 | 확인할 순서 |
| --- | --- |
| 계약 변경 | 서버 상세와 도구 정의 차이 → 승인된 도구·인자 범위 → 필요한 재심사 |
| 정책 조회 실패·불일치 | **보안 관리 정책**의 조회 시각·룰셋·데이터 일치 → 서버 상태와 정책 로드 |
| 관제 미전달 증가 | 수신 서비스 → 자격·인증서 → 전달 워커와 로그 → 최근 전달 성공 |
| 영향 조회의 자료 없음 | SBOM 등 근거 자료의 존재와 범위. 안전 판정으로 처리하지 않습니다. |
| 종료 확인 불가 | 대상 범위와 상태 증거 → 미충족 기준 → 추가 수집과 재판정 |
| 종료 후 남은 설정 | 엔드포인트의 최근 보고와 실제 설정 제거 여부 |

서버에서 운영자가 쓸 기본 확인 명령은 `deploy/`의 `./mint.sh status`, `./mint.sh logs gateway`, `./mint.sh logs agent-service`입니다. 백업·복구·키 관련 문제는 [서버 운영 문서](../../deploy/README.md)를 따릅니다.

## 관리자에게 전달할 정보

다음 정보를 조직의 지원 경로로 전달합니다.

- 발생 시각과 수행하려던 업무
- 화면의 오류 문구 또는 판정 사유
- 호출 번호·추적 ID, 서버·도구 이름
- PC 운영체제·설치 모드·엔드포인트 식별자
- 실행 결과의 **전송 / 실행 / 응답 처리**와 외부 시스템에서 확인한 처리 여부

비밀번호·토큰·API 키·설치 자격을 함께 보내지 않습니다. 화면이나 증빙 파일에 개인정보와 업무 자료가 있으면 조직의 공유 기준을 확인합니다.
