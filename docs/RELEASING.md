# 버전과 태그 관리

제품 판본과 문서 이력을 구분합니다. 문서만 수정·추가한 변경은 Git 커밋과 PR로 추적하며 제품 버전을 올리거나 새 출시 태그를 만들지 않습니다.

## 무엇으로 관리하는가

| 대상 | 기준 | 변경 시점 |
| --- | --- | --- |
| 제품 판본 | 저장소 최상위 [VERSION](../VERSION) | 제품 출시를 준비할 때 |
| 출시 코드 | `v<제품 판본>` 태그 | 검증을 마친 출시 커밋 확정 후 |
| 출시 변경 설명 | [CHANGELOG.md](../CHANGELOG.md) | 해당 제품 출시의 변경을 정리할 때 |
| 문서 보완·오탈자·이미지 | 커밋·PR 이력 | 문서를 개선할 때 |
| 실행 중인 체크아웃 | `./mint.sh status`와 상태 API의 빌드 리비전 | 현재 배포한 커밋을 확인할 때 |

`deploy/mint.sh`는 `VERSION`을 제품 판본과 이미지 태그의 기준으로 사용하고, 빌드 리비전에는 Git 커밋을 덧붙입니다. 따라서 같은 제품 판본에서도 체크아웃이 다르면 `1.0.0+g<커밋>`의 커밋 부분이 달라질 수 있습니다. 이를 새 제품 출시로 취급하지 않습니다.

## 문서만 바꾸는 경우

1. 작업 브랜치에서 Markdown·이미지를 수정하고 제품 동작과 메뉴에 맞는지 확인합니다.
2. 링크·이미지 경로와 문서 구조를 점검합니다.
3. `docs:` 성격의 커밋과 PR로 변경 내용·확인 범위를 남깁니다.
4. `VERSION`, README의 제품 판본 배지, 기존 출시 태그와 과거 출시 기록을 변경하지 않습니다. 문서 수정만을 위한 패치 판본도 만들지 않습니다.

현재 안내서는 [사용자 안내서](user-guide/README.md)에서 찾습니다. 기존 출시 태그를 체크아웃하면 그 출시 당시의 파일이 보이며, 이후에 보완한 문서는 기본 브랜치의 이력으로 확인합니다. 최신 안내서를 기존 태그에 넣기 위해 태그를 옮기지 않습니다.

## 제품을 출시하는 경우

기능·호환성·수정 내용에 맞게 유의적 버전의 주·부·수 판본을 정합니다. 제품 코드를 바꾼 커밋마다 자동으로 출시하지 않고, 출시할 범위를 묶어 검증합니다.

1. 출시할 코드와 배포·PC 키트·정책의 변경 범위를 확정하고 필요한 확인을 마칩니다.
2. `VERSION`, README의 제품 판본 배지, 빠른 설치의 태그와 `CHANGELOG.md`를 같은 출시 기준으로 맞춥니다.
3. 검증 결과와 남은 제한을 출시 커밋·PR에 기록합니다.
4. 확정한 커밋에 제품 판본과 일치하는 주석 태그(`v<제품 판본>`)를 만들고 해당 태그를 게시합니다.
5. 배포는 선택한 출시 태그에서 수행하고 `./mint.sh status`로 판본·준비 상태·정책 일치를 확인합니다.

게시한 출시 태그는 이동하거나 같은 이름으로 덮어쓰지 않습니다. 출시 코드의 수정이 필요하면 새 제품 판본과 태그를 만들고 변경 내용을 남깁니다. 업그레이드·롤백 절차와 백업 주의점은 [서버 운영 문서](../deploy/README.md#업그레이드와-롤백)를 따릅니다.
